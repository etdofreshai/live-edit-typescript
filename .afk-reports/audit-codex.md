# Audit Punch List

1. **Run untrusted previews in an isolated sandbox.** `server/runner.ts:51`, `server/runner.ts:119`, and `server/runner.ts:128` run `npm install`, `npm run dev`, and `npx vite` directly in the main app container with inherited process credentials from `server/runner.ts:77`. Any GitHub repo can run arbitrary install scripts and dev-server code with access to `GITHUB_TOKEN`, `OPENAI_API_KEY`, webhook secrets, filesystem, and network. Suggested fix: move target execution into per-preview containers, Firecracker/gVisor, or a locked-down worker user/namespace with a minimal allowlisted environment and no host secrets.

2. **Eliminate shell command injection in git operations.** `server/runner.ts:29`, `server/runner.ts:30`, `server/runner.ts:32`, `server/runner.ts:33`, `server/runner.ts:148`, and `server/runner.ts:149` interpolate repo, branch, sha, clone URL, and target directory into `execSync` shell strings. Repo and branch currently flow from route params/body in `server/index.ts:112` and `server/index.ts:148`, so metacharacters can become shell syntax. Suggested fix: replace `execSync(string)` with `execFileSync('git', [...])` and validate repo as a GitHub repo name plus sha as a full hex commit before execution.

3. **Fix target directory path traversal and cache-id collisions.** `server/runner.ts:10` builds `targets/${repo}-${sha.slice(0, 7)}` and `server/cache-manager.ts:24` builds the same short-id shape without validating repo or sha. A repo like `../x` or crafted slashes can escape `targets`, and 7-character sha prefixes collide. Suggested fix: reject repo names outside `/^[A-Za-z0-9._-]+$/`, require 40-hex commit shas where applicable, include branch/latest metadata in ids, and verify `path.resolve(dir).startsWith(TARGETS_DIR + path.sep)`.

4. **Do not expose all server secrets to target apps.** `server/runner.ts:77` spreads `process.env` into the child dev server, and `server/runner.ts:85` adds user-supplied env vars. This gives arbitrary preview code access to production tokens. Suggested fix: build a fresh env containing only `PATH`, `HOME`/npm cache vars, port/base values, and explicitly allowed user-provided variables; never forward GitHub/OpenAI/webhook tokens.

5. **Add resource limits for clone, install, and dev servers.** `server/runner.ts:29`, `server/runner.ts:51`, and `server/runner.ts:119` can consume unbounded CPU, memory, disk, process count, and outbound network; only npm install has a time limit. Suggested fix: enforce per-preview CPU/memory/pids/disk/network quotas in the sandbox and add timeouts to clone, checkout, fetch, reset, and server readiness.

6. **Prevent install scripts from running by default.** `server/runner.ts:51` and `server/runner.ts:67` use `npm install`, which executes arbitrary lifecycle scripts before the preview even starts. Suggested fix: use `npm ci --ignore-scripts` when a lockfile exists, otherwise `npm install --ignore-scripts`, then provide an explicit trusted opt-in for repos that require postinstall scripts.

7. **Authenticate or restrict privileged API routes.** `server/index.ts:46`, `server/index.ts:63`, `server/index.ts:89`, `server/index.ts:108`, `server/index.ts:112`, `server/index.ts:148`, `server/index.ts:198`, `server/index.ts:290`, and `server/index.ts:316` are unauthenticated and `server/index.ts:17` allows broad CORS. Public callers can start arbitrary jobs, inspect cache/logs, create branches/PRs, delete cache entries, and spend OpenAI/GitHub quota. Suggested fix: require session/auth or an admin token for mutating and sensitive read endpoints, and lock CORS to the deployed origin.

8. **Fix file-read path traversal checks.** `server/index.ts:240` joins user input with `entry.dir`, then `server/index.ts:243` checks `fullPath.startsWith(entry.dir)`. Paths such as sibling prefixes or encoded traversal can bypass string-prefix checks. Suggested fix: use `const resolved = path.resolve(entry.dir, filePath)` and require `resolved === entry.dir || resolved.startsWith(entry.dir + path.sep)`, and reject absolute paths.

9. **Bound recursive file listing.** `server/index.ts:214` recursively walks the entire target tree synchronously, skipping only `.git` and `node_modules`. Large repos, symlink loops, deep trees, or generated directories can block the event loop or exhaust memory. Suggested fix: use an async walker with max depth/file count/byte budget, skip common build/cache dirs, ignore symlinked directories, and return partial results with a truncation flag.

10. **Make preview startup wait for actual readiness and early exits.** `server/runner.ts:141` sleeps for 3 seconds and `server/runner.ts:143` returns success even if the child exited or never bound the port. The UI then polls for up to a minute in `src/IframeWithRetry.tsx:27`. Suggested fix: wait on port readiness with a bounded timeout, listen for child `exit`/`error` during startup, and return structured startup failure with the last log lines.

11. **Clean up failed preview attempts.** `server/index.ts:119` evicts and `server/index.ts:121` allocates a port before `cloneAndStart`, but `server/index.ts:143` only returns an error on failure. Cloned directories, partial installs, and child processes may remain outside the cache. Suggested fix: track the target dir/process during startup and always stop/remove them in a catch/finally path when no cache entry is added.

12. **Handle concurrent runs for the same repo/sha.** `server/index.ts:116` checks the cache before starting, but simultaneous requests can both miss, allocate different ports, and clone/install into the same `server/runner.ts:24` directory. Suggested fix: add an in-flight promise map keyed by normalized repo+sha/branch so duplicate requests await the same startup.

13. **Cache dependencies across previews.** `server/runner.ts:51` runs a full `npm install` for every cloned commit, and the target dir includes the sha at `server/runner.ts:10`, so cold starts repeat work across nearby commits. Suggested fix: mount a shared npm cache, prefer `npm ci`, and cache `node_modules` by lockfile hash or use pnpm/yarn store-style caching inside the sandbox.

14. **Refresh latest entries by restarting or verifying the dev server.** `server/runner.ts:146` fetches/resets and installs dependencies for latest entries, while `server/index.ts:602` only updates the sha. If Vite crashed, if config changed, or if dependencies require restart, the cached port can serve stale/broken state. Suggested fix: after `pullLatest`, check process/port health and restart the dev server when package/config files changed or the process is no longer alive.

15. **Fix static entry port accounting.** `server/index.ts:133` stores `port: 0` for static entries after allocating a real port at `server/index.ts:121`, but `server/index.ts:171` stores the allocated port even when `type` is static. This wastes ports and makes latest static entries appear as live servers. Suggested fix: only allocate a port after confirming the repo is a Vite app, or consistently store `0` for static entries and release the reserved port.

16. **Limit upload sizes and validate multipart JSON.** `server/index.ts:34` creates an unbounded memory-storage multer instance, and `server/index.ts:323`/`server/index.ts:324` parse request fields without try/catch. Large audio/screenshots can exhaust memory, and malformed JSON can crash the route handler. Suggested fix: configure `multer({ limits: { fileSize, files, fields } })`, validate mime types, wrap JSON parsing, and return 400s for bad input.

17. **Replace default webhook secret and harden signature compare.** `server/webhook.ts:7` falls back to `live-edit-webhook-secret`, and `server/webhook.ts:13` calls `timingSafeEqual` on buffers that may have different lengths, which throws. Suggested fix: require `WEBHOOK_SECRET` in production, fail closed when absent, compare lengths before `timingSafeEqual`, and catch malformed webhook JSON at `server/webhook.ts:28`.

18. **Stop trusting the Host header for webhook registration.** `server/index.ts:183` passes `req.get('host')` into `registerWebhook`, and `server/webhook.ts:63` turns it into a webhook URL. A crafted request can register a GitHub webhook to an attacker-controlled host if the token has hook permissions. Suggested fix: require an explicit `WEBHOOK_URL` for registration and ignore request host in production.

19. **Normalize GitHub owner support or remove misleading route owner params.** `src/App.tsx:21` exposes `/:owner/:repo`, but `src/PreviewPage.tsx:220` posts only `repo`, `server/github.ts:2` hardcodes `etdofreshai`, and `server/runner.ts:27` clones only that owner. Suggested fix: either validate/reject non-`etdofreshai` owners in routes/UI or plumb owner through GitHub API, cache keys, clone URLs, and auth policy.

20. **Deduplicate `IframeWithRetry`.** `src/PreviewPage.tsx:20` defines a local `IframeWithRetry` that duplicates `src/IframeWithRetry.tsx:8`. Behavior and styles can drift, and fixes must be made twice. Suggested fix: import the shared component into `PreviewPage` and delete the local copy.

21. **Split the oversized editor component.** `src/Editor.tsx:66` contains repo selection, branch/PR flows, env editing, cache management, static file browsing, log modals, console capture, and voice integration in one 900+ line component. Suggested fix: extract focused hooks/components such as `useRepoSelection`, `usePreviewCache`, `EnvModal`, `CachePanel`, `StaticFileBrowser`, and `TopBar`.

22. **Remove dead and mismatched dependencies.** `package.json:13` and `package.json:17` list `@types/form-data` and `form-data`, but the server uses native `FormData`/`Blob` per `server/index.ts:8` and no import references exist. `package.json:29` installs React Router v5 types while `package.json:21` uses React Router v7. Suggested fix: remove unused `form-data` packages and the obsolete `@types/react-router-dom` package; rely on bundled v7 types.

23. **Update vulnerable and stale dependencies.** `package.json:16`, `package.json:20`, and the lockfile currently audit with high-severity `multer <2.1.1`, high-severity `path-to-regexp <0.1.13` via Express 4, and moderate `follow-redirects <=1.15.11`. `npm outdated --json` also reports newer wanted versions for `express`, `multer`, `cors`, and `react-router-dom`. Suggested fix: run a targeted dependency upgrade, regenerate `package-lock.json`, and add `npm audit --omit=dev` to CI.

24. **Use production Docker/runtime hygiene.** `Dockerfile:1` uses the full `node:22` image, `Dockerfile:8` runs `npm install --include=dev`, and `Dockerfile:13` starts `npm run dev` with Vite/tsx watchers. This ships dev tooling and runs as root in production. Suggested fix: use a multi-stage Dockerfile with `npm ci`, build assets, prune dev deps where possible, create a non-root user, expose/start only the Express server against built `dist`, and add a healthcheck.

25. **Add a real production server script.** `package.json:10` only builds the client with `vite build`; there is no `start` script that runs the API against built assets. `server/index.ts:569` expects `dist/index.html`, but Docker starts dev mode at `Dockerfile:13`. Suggested fix: add `build:server` or run the server through a compiled/tsx production command, and add `start`/`start:prod` that serves `dist` without Vite's dev server.

26. **Add tests for security-critical helpers and preview flow.** There are no test files or CI configs in the repo, and `package.json:6` has no `test`, `typecheck`, or `lint` scripts. Suggested fix: add unit tests for repo/branch/sha validation, safe target path resolution, webhook signature validation, env filtering, file traversal prevention, and an integration test that stubs GitHub/child processes for `/api/run`.

27. **Add CI gates.** No `.github/workflows` files exist, so type errors, dependency advisories, and Docker build regressions are not caught. Suggested fix: add a GitHub Actions workflow for `npm ci`, `npm run typecheck`, tests, `npm audit --omit=dev`, and `docker build`.

28. **Improve API error handling and client response parsing.** The shared client helpers at `src/Editor.tsx:40` and `src/PreviewPage.tsx:18` call `r.json()` without checking `r.ok`, while server catch blocks like `server/index.ts:143` return raw exception messages. Suggested fix: add a typed API client that handles non-JSON and non-2xx responses, and map server failures to stable error codes plus sanitized messages/log ids.

29. **Document the threat model and deployment requirements.** `README.md:253` documents internals and `README.md:262` gives a minimal Docker snippet, but it does not explain that preview repos execute arbitrary code, which secrets must never reach target processes, how sandboxing/resource limits work, or what GitHub token scopes are required. Suggested fix: add a "Security model" and "Production deployment" section covering sandbox choice, quotas, network policy, env policy, auth, webhook secret requirements, and token scopes.

30. **Move user env vars out of localStorage or mark them as non-secret.** `src/Editor.tsx:196` and `src/Editor.tsx:231` store per-repo env text in localStorage, while `README.md:153` suggests DB credentials/API keys can be stored there. Any same-origin script or compromised preview/proxy path can read them. Suggested fix: store secrets server-side encrypted per user/session, or clearly limit this feature to non-secret public config and scrub values from logs/UI.
